## 8. PERSONAL AI INTEGRATION VALIDATION

**Goal:** the committed provider-independent adapter behaves correctly
against the *real* CloudKit transport — with local data always safe.

Run against `iCloud.com.evenai.app` Development, using the existing
`PersonalAISyncEngine` (unchanged) over the real `LiveCloudKitDatabaseFacade`:

- [ ] **Local authority under failure** — kill the network mid-sync / sign
      out of iCloud mid-sync: sync returns `.failedRetryable`, **all** pending
      changes stay queued, cursor untouched, the local encrypted cache is
      byte-identical afterward.
- [ ] **Deterministic IDs** — a `MemoryRecord` created locally keeps its
      canonical UUID as the `CKRecord.ID` recordName after push and after a
      pull on a second install.
- [ ] **Revisions** — every accepted change appends a local `RecordRevision`;
      revision history is **not** expected in CloudKit (it stays local +
      backup/export) — confirm it is preserved locally, not lost.
- [ ] **Tombstones** — a locally-deleted record propagates `deletedAt`;
      pulling on a second install applies the tombstone.
- [ ] **Incremental sync** — after the first full sync, a single local edit
      produces a pull that returns only that record (per-zone
      `CKServerChangeToken` advancing).
- [ ] **Idempotency** — replaying the same push batch (same
      `idempotencyKey` / same `(id, revision)` set) creates no duplicates.
- [ ] **Retry** — a transient `CKError` (`.networkFailure`,
      `.serviceUnavailable`, `.requestRateLimited`) is classified
      `retryable` by `CloudKitErrorMapper`; the next sync succeeds with no
      data change.
- [ ] **Account binding** — first successful sync writes
      `CloudKitAccountBinding { personalAIUserID, ckUserRecordName, boundAt }`
      to the persisted `FileCloudKitAdapterStateStore`; it survives an app
      relaunch.
- [ ] **Account-switch freeze** — sign into iCloud account B on a device
      bound to A: `CloudKitAccountEvaluator` returns
      `.reconciliationRequired`; `push` / `pull` / `snapshot` throw
      `unauthorized`; **nothing** from A is uploaded into B's database;
      switching back to A resumes.
- [ ] **No cross-user merge** — account A's records never appear in account
      B's private DB and vice versa.
- [ ] **Cloud failure never clears the local cache** — exercise every failure
      classification; the Personal AI memory store is never mutated by a
      failure path.
- [ ] **No accidental duplication of existing local data** — a device with
      existing local Personal AI data doing its first sync converges by
      canonical id; it does not create second copies.

**PASS:** every box checked, with local data provably safe on every failure
path.
**FAIL / STOP:** any data-loss, resurrection, duplication, or cross-user leak
→ stop; the adapter or its wiring needs a fix before any recovery claim.

## 10. INDEPENDENT R2 BACKUP

**CloudKit activation does NOT complete disaster recovery.** CloudKit is the
*primary* copy; if the Apple account or CloudKit itself is lost, the user
still needs an independent copy. **R2 remains a separate workstream** (see
`PHASE2_R2_INDEPENDENT_BACKUP.md` → "REQUIRED MANUAL CLOUDFLARE SETUP FOR
LATER").

Before EvenAI may claim **durable multi-copy cloud recovery**, all of the
following must still be true — none is delivered by finishing CloudKit:

- [ ] A real Cloudflare **R2 bucket** exists (one region).
- [ ] A **secure production authentication path** exists — a deployed Worker
      with one `POST /presign` route that holds the R2 API token in its
      secrets, verifies the caller's identity, derives `ownerTag`
      server-side, rejects keys outside `<ownerTag>/`, and returns a
      short-lived presigned URL.
- [ ] **No R2 secret is embedded in the iOS app or the repo** — the app only
      ever receives presigned URLs (`WorkerBackupCredentialProvider` +
      `URLSessionBackupObjectTransport`).
- [ ] **Encrypted upload** — the app uploads only the AES-256-GCM-sealed
      `.eapb` envelope; R2 never receives plaintext.
- [ ] **Encrypted download** — restore fetches the sealed object and decrypts
      on-device.
- [ ] **Integrity verification** — envelope hash + length, GCM tag, bundle
      checksum, structural validate — all checked before use.
- [ ] **Restore** — a sealed R2 object round-trips to a validated
      `PersonalDataBundle` and imports without touching local data on
      failure.
- [ ] **Wrong-key / corruption handling** — a wrong key or a tampered object
      is rejected with a typed error, local data untouched.
